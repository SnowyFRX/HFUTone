# HFUTone 1.4.6

versionCode **26**

只修更新检测这一条链路，签到逻辑没动。

## 检查更新变灵敏、也不再消耗开发者的东西

- **启动 6 秒后静默查一次**：有新版就在「说明」按钮挂红点，点进去第一行就是下载入口。
  失败不提示、不弹窗、不挡签到。
- **不再使用 `api.github.com`**：那条匿名只有 60 次/小时/IP，校园网 NAT 后面几十人
  共用出口，撑不住。现在只读两条公开文件——jsDelivr 上的 `web/version.json` 和
  GitHub Releases 的 atom feed，都**不限流**，请求由每个用户的设备自己发出，
  中间没有任何中转，也不占开发者账号的任何额度。
- **取所有源里最高的版本**，不再「第一路成功就信」。jsDelivr 的 `@main` 有 12 小时
  缓存，发版后它会滞后，旧逻辑会误报「已是最新」——1.4.5 发布后就是这么翻车的。
- 本地缓存从 6 小时缩到 **30 分钟**。

## 发版流程补了一步

推送后固定 purge jsDelivr，8 秒后所有客户端读到的就是新版本号，不用等 12 小时。

## 已知限制

- 验证码 / 手势 / 签到码 / 二维码 / 没配坐标的位置签到，只记「需人工」，不会硬交。
- 自动签到默认**关**，要在设置里手动打开。
- 安卓的守护进程靠前台服务维持，建议把本应用排除出电池优化。
