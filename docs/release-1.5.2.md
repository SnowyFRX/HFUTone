# HFUTone 1.5.2

versionCode **32**

1.5.1 的通知能用但有两个硬伤，这一版修掉。

## 点击常驻通知会崩溃（已修）

根因是 `RemoteViews` 只认白名单控件。1.5.1 的胶囊用裸 `<View>` 画状态圆点和
横幅竖条，那不是白名单控件——通知能显示（系统兜了一下），但一点击、系统去解析
布局时就抛异常，整个应用崩掉。

现在全换成 `ImageView`；同时去掉子控件上单独的点击绑定（整条通知已经有
`setContentIntent`），跳转 flag 从 `NEW_TASK | SINGLE_TOP` 改成
`CLEAR_TOP | SINGLE_TOP`——main 已经是 `singleTask`，再叠 `NEW_TASK` 等于
另起任务，部分 ROM 上直接崩。

## 通知被折叠进「更多通知」（已修）

通知通道的「重要性」创建后**不能修改**。1.5.1 用 `IMPORTANCE_LOW` 建过一次，
所以它注定被系统收进折叠区。只能换 id 重建：

- 通道 id 改为 `hfutone_status_v2`，重要性提到 `IMPORTANCE_DEFAULT`；
- 声音和振动单独关掉——在主通知区待着，但不出声；
- 旧通道在服务启动时一并删掉，设置页里不会留两行。

## 悬浮通知默认关，改用悬浮窗

国产 ROM 默认关掉 heads-up，而它归系统设置管，应用只能请求不能代开。
所以签到成功的提醒换成**悬浮窗自绘**：顶部深色胶囊，停 4 秒消失，点它回 App。

- 只看「显示在其他应用上层」一个权限，跟通知设置完全无关；
- 悬浮窗成功就不再发通知横幅，同一件事不提示两次；
- 没授权或失败才退回通知横幅；
- 设置 →「其他」→「悬浮提醒」可以直接跳授权页。

## 其他

- 设置里加了「打开通知设置」，直达本应用的「签到提醒」通道页，省得自己翻；
- 崩溃堆栈现在会写到 `Android/data/com.hfutone.app/files/crash.log`，
  连电脑就能看到，下次出问题不用猜。

## 已知限制

- 悬浮提醒需要手动授权「显示在其他应用上层」；
- 个别 ROM 还会限制后台弹悬浮窗，需要的话一并打开「后台弹出界面」；
- 常驻通知必须允许通知权限，否则胶囊看不到（服务仍在跑）。
