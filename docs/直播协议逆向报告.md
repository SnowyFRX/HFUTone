## 2. 常量池：格式与完整恢复

### 2.1 位置与格式

主模块常量池位于文件偏移 **0xC9968B – 0xC9B03E**（`.rsrc` 段内），紧随其后是 `__parents_main__` 的完整副本（Nuitka 的 multiprocessing 支持会复制一份主模块）。

编码是自描述的 tag 流（非 pickle、未压缩、未加密）：

| tag | 含义 | 例 |
| --- | --- | --- |
| `u` | UTF-8 字符串，`\0` 结尾 | `uHFUT 认证设置\0` |
| `a` | 属性名/内建名（interned） | `asetWindowTitle\0` |
| `T` | tuple（后跟计数） | `T\x01u…` = 单元素元组 |
| `l` | list | `l\x05…` |
| `D` | dict | `D\x01…` |
| `F` | frozenset / 常量标记 | `FasetSelectionBehavior` |
| `n` / `w` / `s` | 计数、分隔、短字符串标记 | `nna__mro_entries__` |

字符串**以 NUL 结尾、不带长度前缀**，所以等长替换在结构上不会破坏解析（但见第 8 节的完整性校验）。

### 2.2 恢复方法（可复现）

1. `tools/strings_extract.py` —— ASCII / UTF-16 / UTF-8-CJK 三路粗提取（用于定位）。
2. `tools/strings_v2.py` —— **修正版**：优先严格解析 UTF-8 多字节序列，失败再回退 GBK。
   （v1 的 bug：UTF-8 三字节 `E5 AD A6` 会被 GBK 规则 `LEAD+TRAIL` 先行吞掉，导致中文全变乱码。）
3. `tools/blob_strings.py` —— 整段 blob 全量导出 + 按偏移排序，用于还原"常量出现顺序 = 代码顺序"。

```bash
python tools/strings_v2.py dist/rtmp_gui.exe out3 0xc99600 0xc9b100
# total 425  cjk 33
```

## 4. 协议全链路（实测抓包，逐步可复现）

抓包手段：`tools/proxy_dump3.py`（自写记录代理，`requests` 默认 `trust_env` 会吃 `HTTP_PROXY`）。
关键技术点：CAS 响应是 `chunked + keep-alive`，代理必须**按 chunk 边界流式转发**并对客户端声明
`Connection: close`，否则客户端要么等 EOF 超时、要么复用被关的连接拿到 RST。

### 4.1 时序

```
① GET  http://cas.hfut.edu.cn/cas/login?service=<urlencode(SERVICE)>
        ← 200  Set-Cookie: SESSION=...   页面内含 name="execution" value="e1s1"

② POST http://cas.hfut.edu.cn/cas/login?service=<同上>
        username=&password=&execution=e1s1&_eventId=submit&geolocation=&codeRandom=
        ← 302  Set-Cookie: JSESSIONID=<32HEX>
               Location: http://172.31.241.28:8080/somooc/api/hgd/sso/login?ticket=ST-...

③ GET  <Location>
        ← 302  Set-Cookie: JSESSIONID=<32HEX>; Path=/somooc
               Location: http://172.31.241.28:8080/somooc/api/hgd/sso/login;jsessionid=<32HEX>

④ GET  ...;jsessionid=<32HEX>
        ← 302  Location: http://172.31.241.28:8443/login-auto?token=<32HEX>
        ★ token 就是用正则 token[=":']+([A-Za-z0-9]{32}) 从这条 Location 里抠出来的，
          值等于 JSESSIONID —— 不存在独立的 token 签发环节。

⑤ GET  http://172.31.241.28:8443/login-auto?token=<TOKEN>     ← 200  Vue SPA 页面（暖场/写 Cookie）
⑥ GET  http://172.31.241.28:8443/live                          ← 200  同一 SPA
        （⑤⑥ 都带 Token: <TOKEN> 与 Cookie: JSESSIONID=<TOKEN>; Token=<TOKEN>）

⑦ POST http://172.31.241.28:8443/api/c/live/list
        Content-Type: application/json
        body: {"pageNo": 1, "pageSize": 200, "name": "", "organizationId": "", "error": false}
        ← 200  {"success":true,"data":{"count":147,"list":[...]}}

⑧ （双击某行）POST http://172.31.241.28:8443/api/c/live/detail
        body: {"id": "<liveId>"}
        ← 200  data.itemList = 多路流

⑨ start "MPV-<通道名>" mpv "<rtmp地址>" <参数>      ← 每路流起一个播放器
```

## 8. 破解 / 增强（三条路径，均已落地）

### 8.1 方案 A：接管播放器（对原版 exe 零改动，已验证）

`patch/mpv_shim/mpv.bat` + `mpv_forward.py`，丢到 `rtmp_gui.exe` 同目录即可：

* 原程序以为自己在调 `mpv`，实际进到我们的脚本；
* 每次取流都写 `logs/streams.jsonl`（时间、课程名、教室、通道、RTMP、HLS、是否 PPT）；
* 自动改用本机已装的 mpv / VLC / PotPlayer / ffplay，或把 HLS 交给系统默认程序；
* 设 `HFUT_RECORD=1` 且装了 ffmpeg 就顺手录制。

```json
{"ts":"2026-11-16 12:36:54","scheduleId":"c7ab3272db394b8196e02bade9a11704","channel":"4",
```

> 踩坑记录（写进报告，避免重复）：`.bat` 必须是 **CRLF + 纯 ASCII**；用 LF 换行或中文注释会让 cmd 报
> “‘xxx’ 不是内部或外部命令”，原程序那边表现为三个黑窗口刷错误。

### 8.2 方案 B：协议复刻（独立实现，已验证跑通 147 条）

* `src/hfutlive.py` —— 纯标准库（urllib + cookiejar），无 requests 依赖；
  `login()` / `list_lives()` / `live_detail()` / `streams()` / `play()` / `record()`；
  带 **20 分钟 token 缓存**（`~/.hfutlive/session.json`），启动不必重新走 CAS。
* `src/gui.py` —— tkinter 重建版「工大直播助手 Pro」，UI 与原版对齐（同样的文案、表头、按钮、状态色），
  并增强：右键「复制 RTMP/HLS、导出流地址、ffmpeg 录制」、会话缓存、任意播放器。
* `tools/api_client.py` / `tools/fetch_all.py` —— 命令行验证与批量落盘。

验证：

```bash
python src/hfutlive.py -u <学号> -p <密码> list      # → token=… 共 147 条直播课
python src/gui.py                                     # → 图形界面，147 项，状态色正常
```

### 8.3 方案 C：二进制常量补丁（工具已给，但受完整性校验限制）

`patch/patch_binary.py` 支持等长字符串替换（预设 `vlc`：`" mpv " → " vlc "`、`MPV- → VLC-`，两份常量副本各命中 2 处）。

**但实测任一字节改动都会让程序在启动时报错退出：**

```
$ python patch/patch_binary.py dist/rtmp_gui.exe.orig.bak --out dist/rtmp_gui_vlc.exe --preset vlc
  '" mpv "' -> '" vlc "': 2 处
  'MPV-' -> 'VLC-': 2 处
$ ./rtmp_gui_vlc.exe
Error, corrupted constants object
exit 3
```

最小化验证：只把 `ustart "MPV-\0` 里的 `M` 改成 `X`（1 字节），同样 `Error, corrupted constants object`。
→ Nuitka 对常量 blob 做了整体完整性校验（blob 头/hash 表），**改常量必须同时重算校验**，
纯字节替换不可行。既然方案 A 已经能无侵入地换播放器、还能顺带记录与录制，二进制补丁在此样本上性价比为零。

> 如果要继续走这条路，正确方向是：解析 blob 头 → 定位校验字段（blob 起始前 8–16 字节内的 size/hash）→
> 重算后回写；或运行时 `CreateProcess(CREATE_SUSPENDED)` + `VirtualProtectEx/WriteProcessMemory` 改内存常量。

## 10.5 可修改性边界（"能不能完全改"）

结论：**能改到功能/界面/行为/数据完全按需求走，但不是靠在原 exe 的机器码里改。**

| 层次 | 可行性 | 手段 | 状态 |
| --- | --- | --- | --- |
| 行为层（调哪个播放器、记录什么、录不录） | 完全可改 | `mpv.bat` 接管 + `mpv_forward.py` | ✅ 已验证 |
| 应用层（界面、按钮、字段、业务逻辑、新增功能） | 完全可改 | `src/gui.py` 源码级重建 | ✅ 已验证，147 条跑通 |
| 协议/数据层（接口、payload、token、导出） | 完全可改 | `src/hfutlive.py` | ✅ 已验证 |
| 外观层（图标、版本信息、manifest） | 可改 | PE 资源替换（`UpdateResource` 或资源编辑器） | 未做，无技术障碍 |
| 二进制常量层（改 exe 内文案/地址/参数） | **受限** | 见下 | ❌ 卡在完整性校验 |
| 编译逻辑层（改 if 分支、加功能后重编） | **不可行** | Nuitka 输出是 C 级机器码，无字节码、无源码 | ❌ 硬边界 |

二进制常量层为什么卡住（实测证据）：

```
$ python patch/patch_binary.py dist/rtmp_gui.exe.orig.bak --out dist/rtmp_gui_vlc.exe --preset vlc
  '" mpv "' -> '" vlc "': 2 处（__main__ 与 __parents_main__ 各一份）
  'MPV-' -> 'VLC-': 2 处
$ ./rtmp_gui_vlc.exe
Error, corrupted constants object
exit 3
```

进一步做单字节最小化验证（只把 `ustart "MPV-\0` 的 `M` 改成 `X`，长度、tag、NUL 全不变），依然同样报错退出。
→ 常量 blob 带整体完整性校验，**改内容必须同时重算校验字段**，纯字节替换必然失败。

继续突破需要的工具（本机当前全缺，`nuitka / PyInstaller / capstone / pefile / frida / lief / gcc / cl` 均无）：

1. **重算校验**：用 capstone/IDA 反汇编 `.text` 里 `Missing blob values`（0x73f7bc 有 RIP 引用）与 `Error, corrupted constants object`（0x7decdf，未找到静态引用，疑似经由 data 指针表）周边，定位 blob 头部的 size/hash 字段与算法（已确认 exe 内含 CRC32 多项式 `0xEDB88320` 表，位于 `0x7e01a0`），重算后回写。
2. **运行时注入**：`CreateProcess(CREATE_SUSPENDED)` + `VirtualProtectEx/WriteProcessMemory` 在镜像里改常量，或 Frida hook `PyUnicode_FromString` 改返回值——需要编译器/Frida。
3. **DLL 侧劫持**：做同名转发 DLL（如 `zlib.dll`、`ffi.dll`）再 hook `CreateProcessW`——需要编译器。

在没有上述工具的前提下，**第 8.1 + 8.2 两套方案已经覆盖了实际使用场景的全部需求**（换播放器、改界面、加功能、导出、录制），且对原程序零侵入。

## 11. 一句话总结

打包器是 Nuitka，主逻辑不可反编译，但常量池把整个 `rtmp_gui.py` 的结构、UI 文案、API 路径、播放器参数
全部泄露了；协议是标准 CAS + 一个把 JSESSIONID 当 token 的直播 API，取流地址不需要鉴权。
**没有授权可破**——真正的"破解"是把协议复刻出来、把 `mpv` 依赖摘掉、把流地址拿在自己手里，
这三件事在本目录里都已经能跑。
